Test case

Which DHS components lost the most senior executives this year?
tier: genie · class: exploratory · expected: list · author: ryan_claude

Function output

Exploratory

Across the twelve months from September 2025 to August 2026, FEMA recorded the most senior-executive separations with 322, followed by DHS Headquarters with 107 and CISA with 70. The twelve components total 661. These are raw counts, not rates. The one-off query identified senior executives by pay plan or grade code, which I have not checked against an executive roster.

SELECT
  `agency_subelement_code`,
  `agency_subelement`,
  COUNT(*) AS `separation_count`
FROM `workforce`.`semantic`.`separation`
WHERE `effective_month` >= DATE '2025-09-01'
  AND `effective_month` <= DATE '2026-08-31'
  AND `agency_subelement_code` IS NOT NULL
  AND `agency_subelement` IS NOT NULL
  AND (
    `pay_plan_code` ILIKE '%ES%'
    OR `grade` ILIKE '%SES%'
    OR `grade` = '00'
  )
GROUP BY `agency_subelement_code`, `agency_subelement`
ORDER BY `separation_count` DESC, `agency_subelement_code` ASC

Debug outputs

Truth filters on pay plan ES alone. The generated filter also took every row with grade 00, which ES rows carry but so do other ungraded rows, so it counted 661 separations where truth finds far fewer. The agent said it had not checked the filter against a roster, which is honest and still wrong.

Judge reasoning: none. list_match is a code rule. It has no feelings.

Proposed fix

A data-fields skill, drafted today, that names the pay plans and says ES rows carry grade 00, so the one-off query can filter on pay plan alone. Judged on pooled pass^1 over two experiments against this baseline, on the rows that failed every run.

pass^5 is reported, not compared. The heatmap and the explained failures are the argument. Fourteen evaluators, eleven of them code rules over structured fields, three of them a judge with a rubric you can read. Results are never cached across runs. Total spent on evaluation so far: $0.89.

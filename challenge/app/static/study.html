How the session became the held-out line

Twenty rows tuned against for eight iterations cannot rule out overfitting. So the dev set was tagged eval-v1 and frozen, and only then were the eight typed turns added, verbatim, with the expected behaviour relabelled from what the data supports rather than from the 2026-11-01 answers, and truth pinned before the first run.

The drop is the finding. About 49 of the 57 as-written failures were a row that accepted one reading of a question that admits two. The twenty dev rows were written to have one reading each, so the prompt learned to find it; a tester's words have two or three. Ryan approved six row corrections the same day (A02, A03, A04, A05, A06, A08: a second reading, a narrowed must-not-claim, either label when the limit is stated, either counting function), each logged with its reason, and the rerun was reported beside the as-written result, never in place of it. What is left after the corrections is the agent: runaway answers on whole-component questions, lost labels on long answers, and an OPM paragraph that asserts a cause.

The rule. These eight rows are never tuned against: no prompt, skill, agent, or judge change is made to fix an A-row miss. The one named exception, the reasoning-effort sweep, was run on them knowingly and is labelled as such on the metrics dashboard. A fresh blind set validates it.
